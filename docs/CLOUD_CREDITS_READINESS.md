# Cloud Credits Readiness

Prepared for AWS Activate, Microsoft for Startups and Cloudflare for Startups applications.

## Public verification assets

- Public product website.
- Public GitHub repository with a clear README.
- Architecture, security, privacy and responsible-AI documentation.
- Named founders and contact details.
- Product roadmap with measurable milestones.
- Documented field evidence clearly separated from software traction.

## Current stage

**Stage:** Prototype / pre-launch pilot.

**Evidence base:** UpwardEco-linked recovery activity, a 51-household Jikwoyi pilot, a recognised WasteWise AI MVP and an established operating team.

**Immediate objective:** Deploy a production-grade pilot environment and validate repeat paid waste transactions with estates, SME clusters and recovery partners in Abuja.

## Why cloud credits are required

Cloud credits will fund infrastructure that cannot be responsibly simulated in a static demonstration:

- secure user identity and permissions;
- evidence storage and retention;
- transactional database services;
- asynchronous dispatch and notification workflows;
- AI inference and model monitoring;
- audit logs, observability and backups;
- security testing, WAF, rate limiting and incident response;
- analytics and partner recovery reports.

## 12-month workload plan

### Months 0–3: Standardise

- configure a production cloud environment;
- implement role-based access;
- define pickup verification and evidence rules;
- onboard collectors and establish baseline service metrics;
- implement logs, monitoring, budgets and alerts.

### Months 4–6: Test paid demand

- run paid pilots with estates and SME clusters;
- track repeat requests, response time and settlement accuracy;
- test AI-assisted prioritisation and anomaly review;
- publish pilot-level reliability and cost metrics.

### Months 7–12: Prepare to scale

- publish unit economics and retention;
- improve forecasting and route support;
- add partner reporting and recovery evidence exports;
- complete a security review and disaster-recovery test;
- decide whether geographic expansion is justified.

## Success metrics

| Area | Metric |
|---|---|
| Adoption | Active pilot customers and repeat collection rate |
| Operations | Median pickup response time and completion rate |
| Verification | Percentage of pickups with complete evidence |
| Settlement | Payout accuracy and time to settlement |
| AI | Priority precision, anomaly-review yield and forecast error |
| Cost | Cloud cost per verified pickup |
| Reliability | Availability, error rate and recovery time |
| Impact | Verified material recovered by type and source |

## Budget controls

- provider budgets and threshold alerts;
- separate development, staging and production environments;
- automatic shutdown or scaling limits for non-production services;
- object-storage lifecycle rules;
- reserved capacity only after stable workload evidence;
- monthly cost-per-transaction review.

## Application positioning

SendWaste AI is not asking for credits to host a brochure website. It needs cloud capacity to convert fragmented field operations into a secure, auditable transaction and intelligence system. Each requested service maps to an identified pilot workload and measurable result.
